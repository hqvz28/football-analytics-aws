INFRASTRUCTURE AS CODE

Automated Cloud Provisioning (Terraform)

Automated Resources:

  • S3 Data Lake: Raw, Staging & Processed buckets with AES256 SSE encryption.
  • S3 Lifecycle Policies: Transitions Raw zone objects to Glacier after 90 days.
  • Security Compliance: Enforces Public Access Block across all lakehouse buckets.
  • IAM Least-Privilege: Dedicated execution role for Glue ETL.
  • Athena Workgroup: Query isolation and encrypted results output.
# Terraform: S3 Lifecycle & Glue Job
resource "aws_s3_bucket_lifecycle_configuration" "raw" {
  bucket = aws_s3_bucket.raw.id
  rule {
    id     = "archive-raw-to-glacier"
    status = "Enabled"
    transition {
      days          = 90
      storage_class = "GLACIER"
    }
  }
}

DATA INGESTION

Resilient Ingestion Engine (Python + Boto3)

Key Engineering Features:

  • Exponential Backoff: Automated 429 rate limit detection and polite sleep retries.
  • Structured Logging: Timestamped audit trails for all data transfers.
  • Partitioned S3 Keys: s3://raw/matches/raw/league={code}/season={year}/
  • Metadata Tagging: Checksum, source API ID, and ingestion timestamp headers.
# Ingestion with retry & partition streaming
def upload_to_s3(self, data, league_id, season):
    timestamp = datetime.utcnow().strftime("%Y%m%d_%H%M%S")
    s3_key = f"{self.prefix}/league={league_id}/season={season}/matches_{timestamp}.json"
    
    self.s3_client.put_object(
        Bucket=self.raw_bucket,
        Key=s3_key,
        Body=json.dumps(data).encode("utf-8"),
        ContentType="application/json",
        Metadata={
            "league": league_id,
            "season": season,
            "source": "football_data_api"
        }
    )
DISTRIBUTED ETL

AWS Glue 4.0 PySpark Transformation

Core Data Transformations:

  • JSON Array Explode: Normalizes complex nested structures (competition, teams, scores).
  • Window Deduplication: row_number() over (partitionBy match_id orderBy utcDate desc) guarantees single source of truth.
  • Derived Feature Engineering: Shot conversion rates, outcome categories (HOME_WIN, AWAY_WIN, DRAW), Over/Under 2.5 goals.
  • Columnar Snappy Parquet: Partitioned by season and league.
# PySpark: KPI Calculations & Partitioning
enriched_df = deduped_df.withColumn(
    "match_outcome",
    F.when(F.col("home_score") > F.col("away_score"), "HOME_WIN")
     .when(F.col("home_score") < F.col("away_score"), "AWAY_WIN")
     .otherwise("DRAW")
).withColumn(
    "is_over_2_5_goals",
    F.when((F.col("home_score") + F.col("away_score")) > 2.5, 1).otherwise(0)
)

enriched_df.write \
    .mode("overwrite") \
    .partitionBy("season", "league") \
    .option("compression", "snappy") \
    .parquet(s3_processed_path)
QUALITY ASSURANCE

Automated Data Quality Gatekeeper

Primary Key Integrity

Enforces 0 NULLs and 100% Uniqueness on match_id. Pipeline halts if duplicates exist.

Domain Validity

Verifies categorical values strictly match: HOME_WIN, AWAY_WIN, or DRAW.

ANALYTICS ENGINE

Amazon Athena Serverless SQL & Views

Optimized Analytical Views:

  • Normalized View: v_team_match_performance unpivots home & away into team-centric records.
  • Partition Pruning: Queries filter on season and league, cutting scan costs by 80-90%.
  • Rolling Momentum: SQL Window functions: AVG(points) OVER (ROWS BETWEEN 4 PRECEDING AND CURRENT ROW) 
-- League Table Standings Query
SELECT
    season, league, team_name,
    COUNT(match_id) AS matches_played,
    COUNT(CASE WHEN result = 'W' THEN 1 END) AS wins,
    SUM(goals_for) - SUM(goals_against) AS goal_diff,
    SUM(points) AS total_points,
    ROUND(AVG(possession_pct), 1) AS avg_possession,
    DENSE_RANK() OVER (
        PARTITION BY season, league 
        ORDER BY SUM(points) DESC, (SUM(goals_for) - SUM(goals_against)) DESC
    ) AS league_rank
FROM football_analytics_db.v_team_match_performance
GROUP BY season, league, team_name;

# .github/workflows/ci-cd.yml
name: CI/CD Pipeline - Football Analytics AWS
on: [push, pull_request]

jobs:
  code-quality-and-tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5

          pytest tests/ -v

  terraform-validation:
    runs-on: ubuntu-latest

      - uses: hashicorp/setup-terraform@v3

          cd terraform
          terraform fmt -check
          terraform validate
